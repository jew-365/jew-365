A reminder card is, in order, a `typography.subheading` heading (`custom.reminderN`, numbered from 1), the label under a `field` [SectionLabel](../components/SectionLabel.tsx) (`custom.reminderText`; the sheet of the mitzvah screen keeps `reminder.label`) as a text input, a [ReminderTimingFields](../components/ReminderTimingFields.tsx) block (the select `reminder.timing` over before the start, from the start, before the end, a set time and, only in this form and the mitzvah screen's editor for a custom mitzvah, a follow-up after the end, then the minutes field labelled by what is counted with its -5 / +5 steps, or for `clock` a [TimeField](../components/TimeField.tsx) labelled `reminder.time`); under that sit the clock time it fires at (`reminderClock()`), or an `urgent` warning when it falls outside the hours and more than `HEADS_UP_MAX_MIN` minutes before them (`custom.reminderOutsideWindow`, with `hours` filled by `HEADS_UP_MAX_MIN / 60`; a follow-up outside 1 to `FOLLOW_UP_MAX_MIN` minutes shows `reminder.errors.followUpRange` instead), and a full-width compact `danger` [Button](../components/Button.tsx) (`custom.deleteReminder`, as a content block's delete). The form keeps a `timings` array beside `reminders`, one `ReminderTiming` per reminder (`timingOf()` of each stored one, `fromStart` for a new one, added and removed with them and never saved), so a minutes field that holds 0 never flips the select to another option; the stored shape stays `anchor`, `offsetMin` and `label`. The minutes take digits only (`maxLength` 3), are clamped to the range of the timing (`TIMING_MINUTES`: before the start up to `HEADS_UP_MAX_MIN`, from the start and before the end up to 720, a follow-up 1 to `FOLLOW_UP_MAX_MIN`) and are written through `withTiming()` of [reminderTiming.ts](../utils/reminderTiming.ts): before the start a negative start offset, before the end a negative end offset, from the start a positive one. Save is refused while any reminder falls outside the hours and the `HEADS_UP_MAX_MIN` minutes before them. A follow-up must fall 1 to `FOLLOW_UP_MAX_MIN` minutes after them. Choosing a timing goes through `switchTiming()`: the minutes carry over between before the start, from the start and before the end (before the start from 0 starts on 10), `followUp` starts on `FOLLOW_UP_DEFAULT_MIN` (60), a set time takes the time the reminder fires at now (`reminderClock()`), or the start time (always the start time from a follow-up), and coming back from a set time or a follow-up starts on 0 (10 for before the start); choosing the selected timing changes nothing. A custom mitzvah may store a `clock` reminder and a heads-up (before the start, down to `HEADS_UP_MAX_MIN` minutes), as the mitzvah screen's editor does. There is no rotating-text field (the user's call on 2026-10-11). A content block is text, blessing, link, or a siddur text chosen in a [BottomSheet](../components/BottomSheet.tsx) of `SheetAction`s (the mitzvah texts, then the standalone texts built for the user's nusach by group, so Chabad is never offered Ushpizin); the form holds an unchosen siddur block as a draft with `textId: null` and drops it on save, so only a complete `ContentBlock` is stored. A stored siddur block whose `textId` is no longer in `SIDDUR_TEXT_IDS` (a retired text such as `tzitzit`) shows the name stored on the block, in place of a registry name (`siddurTextName()` returns `null` for it), and is dropped on the next save. ## Local Contracts

- The router root is configured in [../../app.json](../../app.json) as `extra.router.root = "./src/app"`.
- Keep route params validated before using them in services, stores, or navigation.
- A screen whose [BottomSheet](../components/BottomSheet.tsx) holds a text input sets `keyboardShouldPersistTaps="handled"` on its own `ScrollView`: React Native's responder capture follows the React tree, so the screen's scroll view, which sits above the sheet's `Modal` in it, otherwise spends the first tap on a sheet button closing the keyboard and the button never fires. [hilulot.tsx](hilulot.tsx), [rosh-chodesh.tsx](rosh-chodesh.tsx) and [mitzvah/[id].tsx](<mitzvah/[id].tsx>) hold their notice and reminder sheets this way, each pinned by its render suite, as the custom form and Settings do.
- Route-level user-facing copy should use [../i18n/AGENTS.md](../i18n/AGENTS.md) unless it is narrow, static, and intentionally local.
- Screens should compose services, stores, and reusable components rather than duplicating domain logic.
- Every literal size in a screen (a width, height, font size, line height, icon or tile `size`, `hitSlop`, gap, padding, margin, offset or named size constant that no token matches) goes through `scaled()` from [../theme/scale.ts](../theme/scale.ts), at module scope for a constant, so it grows and shrinks with the display size and a tile, an icon and its text keep their proportions at every step. A constant a screen measures against (a row height behind a scroll offset, a cell size) is scaled once, where it is declared. What stays as written: borders (`borderWidth`, hairlines), the stroke of an icon in its own `viewBox` units, opacity, flex, `aspectRatio`, `zIndex`, durations, counts and thresholds counted in scroll pixels. The points quoted in the AGENTS.md files of this folder are the values at the default display size. [__tests__/uiScale.render.test.tsx](__tests__/uiScale.render.test.tsx) renders the reader and the mitzvah screen at 0.8 and at 1.2 inside `jest.isolateModules`.
- A row of selectable pills is [ChipRow](../components/ChipRow.tsx), a settings card is [SettingsSection](../components/SettingsSection.tsx), a ticking clock is [useNow](../hooks/useNow.ts), and the stage line that home and the taharah dashboard show is `renderHint(stageHint(…))` from [summary.ts](../utils/taharah/summary.ts): a screen never keeps its own copy of any of them.
- A screen never keeps its own copy of the mitzvah list, the user settings or the check-in input ([useDayModel](../hooks/useDayModel.ts)), the mitzvah display name (`mitzvahName()` in [mitzvahName.ts](../utils/mitzvahName.ts)), the remaining-time and clock formatting (`formatRemaining()`, `clockOf()` and `clockRange()` in [clock.ts](../utils/clock.ts)), or a weekday or month name, which comes from `formatDate()` in [../i18n/index.ts](../i18n/index.ts) (`formatDayLine()` in [DayStepper.tsx](../components/DayStepper.tsx) for the weekday · day month line), never from Luxon's `toFormat`.
- The tab navigator ([(tabs)/_layout.tsx](<(tabs)/_layout.tsx>)) passes `detachInactiveScreens={false}` to `Tabs` on every platform and sets no `freezeOnBlur`, on the navigator or on any tab. Before 7.18.8, `@react-navigation/bottom-tabs` drove each tab's detached state from an `Animated` value under `animation: 'fade'`, and under Fabric on iOS that sometimes left the focused tab detached: a blank page under a visible tab bar (react-navigation#12755, react-native-screens#3824). The app carries 7.18.8, which fixes that upstream (commit 9bfc8d0; the pinned set is in the root [AGENTS.md](../../AGENTS.md) Release and Updates), and keeps `detachInactiveScreens={false}` as a second guard. `freezeOnBlur` stays unset: it never took effect while an animation was set (react-navigation#12621), and without the animated path it could start freezing tabs. `animation: 'fade'` and `lazy: false` stay, so every tab mounts at launch and keeps its React tree and state for the life of the app. With the option off, bottom-tabs 7.18.8 renders each tab inside the plain `View` that `react-native-screens` falls back to, whose `display` follows the tab's activity: the focused tab is `display: 'flex'` at every moment, mid-fade included, and an inactive tab is `display: 'none'` once the fade has ended (under 7.15.11 it stayed `flex`, hidden only by the fade's opacity, because its activity was an `Animated` value and not a number). On iOS under Fabric a `display: 'none'` subtree has no native views (React Native skips a hidden subtree there, never on Android), so every tab switch on iOS drops the left tab's native views and rebuilds the entered tab's from its kept React tree: keep a tab's state in React or a store, never in a native view, and check a heavy tab's switch and scroll position on a real iPhone after any bottom-tabs change. Keep `detachInactiveScreens={false}` after any bottom-tabs upgrade. Suite: [__tests__/tabsLayout.render.test.tsx](__tests__/tabsLayout.render.test.tsx), which renders the shipped layout's props through the real expo-router and pins that display contract, and also fails on a second copy of the navigation packages or on a bottom-tabs older than 7.18.8.
