# AGENTS.md

## Purpose

- Own mitzvah detail routes for static and custom mitzvot.

## Ownership

- [[id].tsx](%5Bid%5D.tsx) renders mitzvah details, reminders, content blocks, and detail-level actions, including the "פתח נוסח" button into [../siddur/AGENTS.md](../siddur/AGENTS.md). Its header is [ScreenHeader](../../components/ScreenHeader.tsx) with the mitzvah's [IconTile](../../components/IconTile.tsx) (`iconFor(mitzvah.icon)`) as `leading` and the next-reminder preview as its child, and the delete-reminder confirmation is a [ConfirmDialog](../../components/ConfirmDialog.tsx). Its cards are padded [Card](../../components/Card.tsx)s, "פתח נוסח" and the reset are the shared [Button](../../components/Button.tsx) (`secondary` for the reset), the next-reminder line is `goldText`, back replaces to home when there is nothing to go back to, and an unknown id shows a [ScreenHeader](../../components/ScreenHeader.tsx) titled `detail.notFound` with the back pill instead of a dead end.

## Local Contracts

- Use [../../data/customMitzvotAdapter.ts](../../data/customMitzvotAdapter.ts), `getAllMitzvot()`, or `findAnyMitzvah()` when a detail route must include both static and custom mitzvot.
- For Chok LeYisrael the screen opens with [ChokAddonCard](../../components/ChokAddonCard.tsx). While the add-on is not installed (`useChokStore`), the window and the next-reminder preview are not computed, the settings switch is disabled with `chok.addon.enableAfterDownload` under it, and the reminders card is not drawn.
- For Selichot the screen opens with [SelichotAddonCard](../../components/SelichotAddonCard.tsx); while the user's nusach file is missing neither the window nor the next-reminder preview is computed (the header reads `-`, no text button), and the switch and the reminders stay as they are; both appear the moment the file installs.
- Reminder edits must stay compatible with [../../services/AGENTS.md](../../services/AGENTS.md) scheduler contracts.
- Reminders are added and edited in [ReminderEditor](../../components/ReminderEditor.tsx), a [BottomSheet](../../components/BottomSheet.tsx) holding a [SegmentedControl](../../components/SegmentedControl.tsx) for the anchor (start, end and, for every mitzvah, a set clock time through a [TimeField](../../components/TimeField.tsx): drawn inline in the editor's sheet; for a custom mitzvah also the follow-up after the end; the screen passes `mitzvah` and the user's `location` and `settings`), the label and offset fields and Save; the sheet's own close button is the only way out besides Save. Save accepts a reminder that `nextReminderAt()` would fire at least once in the scheduler's lookahead, whatever the window shown today (a Friday's ends at candle lighting), and refuses one that never fires with `reminder.errors.outsideWindowToday`, or `reminder.errors.outsideWindowNext` when the window it names is not today's. Rows are listed in trigger order (`buildTriggerTime()` against the window shown; ties, and a screen with no window ahead, keep the stored order). Edit and delete use the stored index, so notification ids never change. Each row adds `detail.reminderNextAt` with `nextReminderAt(mitzvah, [reminder], scope)`, and nothing when it is null. A reminder row's title is `reminderLabel(reminder, name)` (the delete confirmation names it the same way), and its `key` is the index with the anchor and offset, never the label, which may be empty; the row reads its anchor label and offset (`+30 דק'`; a follow-up reads `reminder.anchor.followUp` and `+60 דק'`), or for a `clock` reminder the `HH:MM` it fires at (`minutesToTime()`). The screen renders no `Modal` and no `useQuietBlock()` of its own: the sheet and the dialog gate themselves on the quiet block. A reminder row's delete button draws the `close` icon, the add row the `plus` icon, and the legend under the time window a filled circle `View` in the ribbon's safe, warning or urgent colour, never a text glyph.
- The reminder list is `remindersOf(active, mitzvah)` from [useMitzvotStore.ts](../../stores/useMitzvotStore.ts). The settings switch, named `detail.settings`, goes through `setMitzvahEnabled()` of [useNeedsReminderDialog()](../../hooks/useNeedsReminderDialog.tsx): switching on with no reminder leaves the mitzvah off and opens the dialog, whose Settings scrolls the screen to its end, the reminders card, rather than opening the editor sheet while the dialog closes. A row's delete on an enabled mitzvah with one reminder opens no confirmation and shows `reminder.errors.lastReminder` (`typography.small` in `urgent`) under the rows until a reminder is saved, the reminders are reset or the switch changes.
- Content block rendering must support text, blessing, link and siddur blocks without breaking Hebrew-first layout. `ContentBlockView` draws a siddur block as a link-style row captioned `detail.openSiddur` that pushes the reader at `/siddur/<textId>` with no date, so the reader resolves the text for the day in effect. A siddur block whose `textId` is no longer in `SIDDUR_TEXT_IDS` (a retired text) renders nothing.
- The "next reminder" preview is `nextReminderAt()` from the scheduler facade: the first reminder the scheduler would fire, across windows. Once every reminder of the open window has fired, or the window is marked done or skipped, it names the next window's first one, up to ten days ahead and past a Shabbat / Yom Tov block, never inside it. It reads the reminders on screen and the completions and skipped maps, so a mark moves it at once; the screen keeps no filter of its own. The header line and every row's `detail.reminderNextAt` render only while the mitzvah is enabled: a switched-off mitzvah schedules nothing, so it names no next reminder and the switch brings both back. Times print on the location's clock as `dd/MM HH:mm` (`fireTimeText()`).
- The window shown and the "פתח נוסח" button come from `currentOrNextWindow()`, so a night window still open after midnight wins over tonight's; the button shows only when `hasSiddurText()` is true for it and passes the window's day, `dateKey(window.date)`, as `date`: a location date, which after midnight is yesterday's for a night window, not the device's civil date. For Chok LeYisrael it passes no `date`, as home's card does: the reader's own default, the same as the More tab opens, shows the portion of the moment, so on Thursday night it opens ליל שישי, which no `date` can name.
- The header subtitle is the cycle and the window as `clockRange()` from [clock.ts](../../utils/clock.ts): an end on a later calendar day than the start or than the window's own day (`window.date`), on the location's clock, reads `detail.timeRangeNextDay` ("05:27 עד 05:28 למחרת" for Chok LeYisrael, the Omer and maariv; "00:42 עד 09:31 למחרת" for Selichot, whose window lies wholly after the day it belongs to). A window whose end is two or more calendar days after its start reads `detail.timeRangeDays` with both dates (`14/10 18:37 עד 26/10 03:44` for Kiddush Levana's period). It says "the next day", not "tomorrow", because after midnight the window shown can be yesterday's. The subtitle and the two clocks beside the time ribbon print on the location's clock (`location.tz`), like every reminder time on the screen. With no window in `currentOrNextWindow()`'s nine-day look-ahead, a custom mitzvah whose current schedule starts after today's app day (`customStartsOn()` in [customMitzvah.ts](../../utils/customMitzvah.ts)) shows `custom.startsOn` with that date (`scheduleDateLabel()` in [customMitzvah.ts](../../utils/customMitzvah.ts)) in place of `-`.
- A registry `description` prints in its own [Card](../../components/Card.tsx) under the time window: `description.en` in English when it exists, else `description.he` (maariv's "לכתחילה עד חצות הלילה").
