# AGENTS.md

## Purpose

- Own visual tokens, typography, colors, shadows, and theme provider behavior.

## Ownership

- [tokens.ts](tokens.ts), [colors.ts](colors.ts), [typography.ts](typography.ts), [scale.ts](scale.ts), and [shadowStyle.ts](shadowStyle.ts) own theme primitives.
- [colors.ts](colors.ts) owns the six palettes (`THEMES`, `THEME_NAMES`, `ThemeName`): four light ones, gold (`T_LIGHT`, the default: warm cream page, warm-white cards, orange accent; the owner's 2026-10-21 redesign), and pink, purple and blue (gold's style in a rose, violet and blue hue), and two dark ones, dark (night navy with the orange accent) and plum (dark plum, rose accent), listed in `DARK_THEMES`, the one place `isDarkTheme()` reads. Palette ids never change, so no store migrates. `paletteForGender(gender, current)` beside it maps a gender answer to a palette inside the current light or dark class (light: gold for male, pink for female; dark: dark for male, plum for female), so purple and blue land on gold or pink; [../stores/taharahOptIn.ts](../stores/taharahOptIn.ts) `chooseGender()` is its one caller. It also owns `BRAND` (`navy`, `gold`, `onGold`, `parchment`, `white`), the default palette's identity read off `T_LIGHT`, which the provider-free error boundary draws with (the logo has its own generated colours), and the `overlay` token, the scrim behind every sheet and dialog.
- [tokens.ts](tokens.ts) owns `spacing` (xs 4, sm 8, md 12, lg 16, xl 20, xxl 28, xxxl 40) and `radius` (xs 4, sm 8, md 12, lg 16, xl 20, xxl 24, full 999). [typography.ts](typography.ts) owns the `typography` variants (display 28, title 22, heading 17, subheading and body and bodyBold 15, caption and captionBold 13, small 12, micro 11), `fontFamilies` and `APP_FONTS`, the list of font names the root layout loads. The numbers in this paragraph are the values at the default display size (scale 1); every `fontSize`, `lineHeight`, `spacing` value and `radius` value except `radius.full` (999) is passed through `scaled()`, and the durations are unchanged.
- [scale.ts](scale.ts) owns the display size (the owner's request, 2026-10-26: one setting that makes text, buttons and spacing smaller or larger across the app). `UI_SCALES` are the seven steps `[0.8, 0.85, 0.9, 0.95, 1, 1.1, 1.2]`, `DEFAULT_UI_SCALE` is 1 (today's size) and `isUiScale()` is the one check that a value is a step. `UI_SCALE` is the launch scale, read once when the module loads: `readStoredUiScale()` parses the persisted `user-store` string (`{ state: { uiScale } }`) from the main MMKV instance of [../services/StorageService.ts](../services/StorageService.ts) and returns a valid step, else the default, and never throws; under Jest (`process.env.JEST_WORKER_ID`) it is the default, so every existing suite sees today's numbers. `scaled(value)` is `Math.round(value * UI_SCALE * 2) / 2`, half-point steps, and the identity on an integer at scale 1. `scaledBy(value, scale)` is the same rounding at any scale, and `rescaled(value, scale)` turns a size already built at the launch scale back into its base (`Math.round(value / UI_SCALE)`, exact for every step because the bases are integers) and scales that by another step, so Settings previews the real result of a pending step. `__setUiScaleForTests(scale)` is the test hook: it sets the launch scale of the current module registry, so a test loads [scale.ts](scale.ts), sets the scale and only then requires [typography.ts](typography.ts) and [tokens.ts](tokens.ts) inside `jest.isolateModules`, which keeps both plain objects (see [__tests__/scale.test.ts](__tests__/scale.test.ts)). The scale is read once at launch because every screen builds its styles once, at module scope (`StyleSheet.create`): a change is saved in `useUserStore.uiScale` ([../stores/AGENTS.md](../stores/AGENTS.md)) and Settings reloads the app with `reloadApp()` from [../services/appReload.ts](../services/appReload.ts), the function the root layout also reloads with for a change of direction. The phone's own font size keeps applying on top.
- [tokens.ts](tokens.ts) also owns `motion`, the history tab's animation numbers: the two bezier curves, durations in milliseconds, staggers, the tab and press distances and scales, the badge spring the in-view share, throttle and settle delay. Distances stay unscaled.
- [sky.ts](sky.ts) owns the hero's fixed scene palette (`SKY` keyframes, `SKY_SCENE`), the one place outside the palettes where scene colours live; [../utils/dayArc.ts](../utils/dayArc.ts) interpolates it.
- [colors.ts](colors.ts) also owns the colour math the calendar fills use: `blendHex(top, bottom, share)` (lowercase `#rrggbb`), `contrastRatio(a, b)` (WCAG) and `readableOn(fill, candidates)` (the candidate with the highest contrast); `CALENDAR_PARTIAL_SHARES` holds the three partial-day shares (0.22, 0.40, 0.55) of gold over the page that the history calendar blends, chosen so the day number reaches 4.5:1 on every palette, and `missedTone()` / `doneTone()`, the fills, inks and ring colour home's My day gives a missed and a done entry from the palette's `urgent` and `safe`, and `lateTone()`, the fill, ink (4.5:1 or more on its fill in every palette, pinned by [../utils/__tests__/lateMarks.test.ts](../utils/__tests__/lateMarks.test.ts)) and ring of a late mark from the palette's `warning`, which My day, the mitzvah cards and the history tab's day sheet share. Suite: [__tests__/colorMath.test.ts](__tests__/colorMath.test.ts).
- [ThemeProvider.tsx](ThemeProvider.tsx) owns runtime theme access: it resolves `useUserStore.theme` to `{ colors, isDark, name }` and syncs the OS appearance through `Appearance.setColorScheme`, so alerts, the keyboard and switches follow the palette.
- Theme tests live in [__tests__/](__tests__/).

## Local Contracts

- A new token is added to every palette in `THEMES`; the theme test pins identical key sets.
- `gold`, `onGold` and `goldLight` are the accent tokens of every palette, rose in the plum theme and so on, so a screen never assumes they are yellow. `gold` is a fill, never a text colour: the orange reads 2.5:1 on the card in the gold palette. Accent text on `surface`, `bg` or `goldLight` uses `goldText` (a tone of its own, never the accent itself: darker than the accent on a light palette, lighter on a dark one), and a label on an `urgent` fill uses `onUrgent`. `goldWash` and `goldWashStrong` are the accent as a faint tint, the `gold` value with an `09` and an `18` alpha suffix (so 8-digit hex, the one form besides 6-digit hex and `rgba` the theme test accepts), `goldWash` for the schedule's current row, `goldWashStrong` for the Settings search's focused setting and the days inside a [CalendarRangePicker](../components/CalendarRangePicker.tsx) range. Text on a `gold` fill uses `onGold`, never a literal white. Headers draw on the page tokens (`bg`, `text`, `textSub`, `goldText`) and the tab bar on `tabBg`; no screen draws a coloured header band, except home's hero sky.
- The four light palettes share the status colours (urgent, warning, safe). Every palette follows the rules carried from gold, approved on the palette board [../../design/palettes-2026-10-24/index.html](../../design/palettes-2026-10-24/index.html) on 2026-10-25: a light palette's `surface` is a white tinted toward its hue, never neutral and within 25 degrees of its page's OKLab hue, and its `bg`, `surface2` and `border` sit gold's OKLab lightness steps below the card (within 0.003); a dark palette keeps its `bg` and `surface` and sets `surface2` and `border` gold's steps above the card; `tabBg` is `surface`; `goldText` is darker than `gold` on a light palette and lighter on a dark one; `onGold` is dark ink wherever black reaches 4.5:1 on `gold`, else `#FFFFFF` (purple and blue); `shadow` and `shadowStrong` are one hue-tinted colour at 0.08 and 0.18. No two palettes share a `bg`, `surface` or `gold`. The theme test pins every rule.
- The theme test also pins WCAG contrast floors of 4.5 or more: the key pairs `text`, `textSub` and `goldText` on `surface` and `onGold` on `gold` in a test of their own, and text/bg, text/surface2, textMuted/surface, goldText/bg, goldText/goldLight, onUrgent/urgent, urgent/urgentBg and urgent/surface, and `text` and `textSub` over `goldWashStrong` laid on `surface`, so a palette edit that breaks readability fails the suite; it reads hex tokens only. Every palette name has a `settings.theme.<name>` label in both dictionaries, pinned by the same suite.
- The theme picker is [ThemeSwatchRow](../components/ThemeSwatchRow.tsx), never a local copy: each palette's `bg`, its `surface` as a ring inside it, and its `gold` as the dot.
- Keep typography compatible with the Heebo and Noto Serif Hebrew font loading in [../app/_layout.tsx](../app/_layout.tsx). Noto Serif Hebrew is the prayer-text family because it covers every nikud and cantillation mark; Heebo does not.
- Any new literal size in a component or screen (a font size, a line height, an icon size, a fixed box width or height, a spacing or radius that no token matches) goes through `scaled()` from [scale.ts](scale.ts), or it stays the same size at every display size.
- New UI should use theme tokens and `useTheme()` instead of one-off styling. A screen or component never writes a spacing or radius number where a token matches (values 1 to 3, hairlines and fixed box sizes are not spacing), never writes a white literal (a label on a `gold` fill is `onGold`, on `urgent` it is `onUrgent`, anything else white is `BRAND.white`), and never sets `fontWeight` on Heebo text: it takes a `typography` variant or a `fontFamilies.heebo` family. [../app/__tests__/designSystem.test.ts](../app/__tests__/designSystem.test.ts) guards the glyph, white, translucent white, `fontWeight` and font-name rules, the header split between stack screens and tabs, and that no file reads a `colors.header*` token or keeps a screen-local card or button style.

## Work Guidance

- Prefer extending existing tokens over scattering hard-coded colors or spacing.
- Coordinate token changes with affected components and screenshots/manual checks when visual risk is high.

## Verification

- Run `pnpm test -- src/theme/__tests__/theme.test.ts` and `pnpm test -- src/app/__tests__/designSystem.test.ts` after token, color, typography, or provider changes.
- Run `pnpm test -- src/theme/__tests__/scale.test.ts src/app/__tests__/settings.display.render.test.tsx` after changing [scale.ts](scale.ts), the spacing, radius or typography tokens, or the Settings display size.
- Run `pnpm test -- src/components/__tests__/ThemeSwatchRow.render.test.tsx` after a palette change; it pins that the six swatches draw six different cards.
- Run `pnpm typecheck` after theme type changes.
