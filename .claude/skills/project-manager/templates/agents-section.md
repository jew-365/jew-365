## Project records

Three root files say what is open, what is done and where the project stands. Every agent keeps them current in the same change as the work, never in a later pass:

- [not-close.md](not-close.md) holds every open item: tasks, bugs, open questions and other open items. New open work goes there, never into a separate tasks, bugs or questions file. The change that closes an item (done, and its expected result checked) removes it from there and adds its entry to [action-log.md](action-log.md) in the format that file states: what it is, when and where it was requested or found, how it was verified, its version, and whether it is committed, pushed and live, on which channel. A check that could not run yet stays in not-close.md as an open item. Work closed without ever being an item there (a fix found and made in one pass) gets an entry too.
- Each later step updates that entry's fields in the same pass: a commit fills Committed with the hash and subject, a push sets Pushed, a release or deploy sets Live to its id and Channel to its environment (the label replaces the `expected` one), a build or an upload names the build id, its version and where it installs from, and a rollback says what replaced it.
- [state.md](state.md) changes whenever the release or distribution status changes: a release, deploy or rollback, a build, an upload, a review result, a version raise. Its facts are read from the live systems, the consoles or the release log, never assumed, and it carries the date and the commit it was written at.
- A value no record proves is written `unknown`, never guessed; a tag proves a version, not a deploy. An open item is never deleted or moved without the owner's agreement that it is closed; while the owner holds that cleanup, the item is marked `Closed, awaiting move` and stays. An item the owner drops moves to action-log.md as a `Declined:` entry with the owner's words and date.
