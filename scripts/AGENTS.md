# AGENTS.md

## Purpose

- Own local workflow scripts and Expo config plugins that affect development startup or generated native behavior.

## Ownership

- [withExactAlarmPermissions.js](withExactAlarmPermissions.js) caps `SCHEDULE_EXACT_ALARM` at `maxSdkVersion=32` so exact alarms work on every Android version without triggering Google's exact-alarm declaration form.
- [free-port.js](free-port.js) frees a local TCP port before `pnpm web`, cross-platform.
- [test-timezones.js](test-timezones.js) runs the suite once per zone (UTC, Asia/Jerusalem, America/Los_Angeles, Pacific/Kiritimati). It puts `TZ` and `JEST_TZ` in the environment of the Jest process it spawns, so Node resolves the zone at startup and every worker inherits it. Extra arguments are forwarded to Jest.
- [jest-timezone-setup.js](jest-timezone-setup.js) is a Jest `setupFiles` guard. When `JEST_TZ` is set, it fails the run unless the test process really runs in that zone.
- [withMitzvahNotificationAction.js](withMitzvahNotificationAction.js) is an Expo config plugin that injects Android notification action handling.
- [withAndroidBackupRules.js](withAndroidBackupRules.js) writes `res/xml/jew_365_backup_rules.xml` (Android 11 and below) and `jew_365_data_extraction_rules.xml` (cloud backup and device transfer, Android 12 and up) and points the manifest's `fullBackupContent` and `dataExtractionRules` at them. Both list the same `BACKED_UP` includes: the main MMKV file, its `.crc` and React Native's `I18nUtil` preferences. An `<include>` turns every other file off, so the taharah files, the secure store, expo-notifications and expo-updates stay out. [../app.json](../app.json) passes `configureAndroidBackup: false` to `expo-secure-store`, whose own rules would otherwise compete for the same attributes.
- [withAndroidLegacyHebrewLocale.js](withAndroidLegacyHebrewLocale.js) writes the Android strings of the config's `locales.he` file (its top-level keys and its `android` object, the way Expo writes `values-b+he`) to `res/values-b+iw/strings.xml`. Android resolves a Hebrew device locale through the legacy code `iw`, so Expo's `values-b+he` alone left the launcher, Settings and system dialogs on the English `values` name. It reads `locales.he` from the resolved config, so the preview variant gets `יהודי 365 P`. A config `iw` locale would do the same on Android but add an `iw.lproj` to the iOS build, which is why this is an Android-only plugin.
- [check-dox.js](check-dox.js) enforces the mechanical half of the DOX contract: dead links, plain-text file references, section order, and Child DOX Index accuracy.
- [jest-asset-stub.js](jest-asset-stub.js) stands in for the siddur and places asset modules under Jest, where Metro asset resolution does not exist.
- [places/build.js](places/build.js) backs `pnpm places:build`: plain Node with `curl` and `unzip`, it downloads into a `.cache` folder beside it (gitignored; `--offline` uses it as is) the Central Bureau of Statistics' list of localities (`bycode2024.xlsx`, read straight from its XML, ITM coordinates turned into WGS84 by the Transverse Mercator inverse) and GeoNames' `cities15000`, `countryInfo`, `admin1CodesASCII` and `alternateNamesV2` (Hebrew names: the preferred, else the short, never a historic or colloquial one), and writes [../assets/places/world.places](../assets/places/world.places): every CBS locality (Israel and Judea and Samaria, `IL`, `Asia/Jerusalem`, its average height, the common GeoNames English name of a city within 3 km as its English name when that name is plain, the CBS spelling then kept as `aka`), every GeoNames city outside Israel not within 3 km of a CBS locality (Battir beside Betar Illit), largest first, as compact JSON (`zones`, `countries` with Hebrew and English names, `admins`, `places` rows). GeoNames changes daily, so the output is committed and a rebuild is a reviewed change; never edit it by hand.
- [publish-update.js](publish-update.js) backs every `pnpm update:*`. It reads the update messages EAS holds for the channel's branch and the [../app.json](../app.json) `version` (the runtime version, by the `appVersion` policy) and takes the next number: one above the highest `<version>-<n>:` message prefix, or, when no message carries one, one above the count of updates. It prefixes `--message` with `<version>-<n>: `, puts `n` in `EXPO_PUBLIC_UPDATE_NUMBER`, which Metro inlines into the bundle, and runs `eas update --clear-cache` so no cached transform keeps an older number. An update for the `preview` channel also gets `APP_VARIANT=preview` in its environment, because `eas update` ignores the `env` of the build profiles and [../app.config.js](../app.config.js) would otherwise embed production's identity in the preview app's update. Every other channel gets `APP_VARIANT` removed from its environment (`updateEnv()`), so a variable left in the shell never ships the preview identity to production. A branch EAS does not know yet starts at 1. It refuses to publish without `--message` or when EAS cannot list the branch. On the `production` channel it also refuses unless `WHATS_NEW` in [../src/data/guide.ts](../src/data/guide.ts) has an entry whose `label` is the `<version>-<n>` it is about to publish (`whatsNewLabels()` reads the file as text: a label is `label:` and a single-quoted `<version>-<n>`), and its message names the missing label. `--skip-whats-new` never reaches EAS and passes the check only with a `--message` that starts with `Rollback to `. `main()` returns the exit code, and `requireWhatsNew()` and `whatsNewLabels()` are exported for [__tests__/publishUpdate.test.js](__tests__/publishUpdate.test.js).
- [guide/build.js](guide/build.js) backs `pnpm guide:build`. The guide's source, [../src/data/guide.ts](../src/data/guide.ts), is TypeScript that only Jest's transform loads, so the build runs the `guide web copy` cases of [../src/data/__tests__/guide.test.ts](../src/data/__tests__/guide.test.ts) with `GUIDE_WRITE=1`, which makes them write [../docs/guide/index.html](../docs/guide/index.html) and [../docs/guide/en/index.html](../docs/guide/en/index.html) from `renderGuideHtml()` before they check them. It starts Jest through `npx`, like [test-timezones.js](test-timezones.js): a `node` spawn of Jest's own bin could not resolve Babel's runtime under pnpm. Never edit the outputs by hand.
- [logo/export.mjs](logo/export.mjs) is the second half of `pnpm logo:build` (the first is [../design/jew365-concepts/vector/build.mjs](../design/jew365-concepts/vector/build.mjs), which draws the logo SVGs and writes `mark-o-meta.json`). Plain Node plus a Chromium-based browser, found from `CHROME_PATH`, then the standard Edge and Chrome paths on Windows and macOS, then Chrome, Chromium and Edge on `PATH`; it fails with a clear message when there is none. It renders each SVG in the headless browser with a transparent background, crops the screenshot, and writes with its own PNG encoder: [../assets/icon.png](../assets/icon.png) opaque RGB on white, framed as the owner's image frames the mark (`framed()` maps `icon.frame` of `mark-o-meta.json`, the white square of that image, onto the 1024 canvas), [../assets/adaptive-icon.png](../assets/adaptive-icon.png) and [../assets/adaptive-monochrome.png](../assets/adaptive-monochrome.png) from the full mark (mark-o.svg, the bell and the book included) drawn to a 0.255-width radius, well inside the 66/108 safe circle it still checks, because Samsung's launcher crops past that circle (a mark that filled it was cut on a real phone, 2026-10-21), [../assets/splash.png](../assets/splash.png) and [../assets/splash-dark.png](../assets/splash-dark.png) inside 0.96 of their width, [../assets/notification-icon.png](../assets/notification-icon.png) as a white 96 px silhouette and [../assets/favicon.png](../assets/favicon.png) at 48 px, which it also copies to [../docs/favicon.png](../docs/favicon.png) for the site, beside copies of mark-o.svg and mark-o-dark.svg as [../docs/logo.svg](../docs/logo.svg) and [../docs/logo-dark.svg](../docs/logo-dark.svg) and [../docs/favicon.svg](../docs/favicon.svg), both marks in one file that `prefers-color-scheme` switches. It refuses a file whose transparency or ink radius is wrong, prints each file's size and colour type, then writes [../src/components/logo.generated.ts](../src/components/logo.generated.ts) (the SVG strings and aspect ratios behind `AppLogo`) and formats it with Prettier. It also writes the red preview variant's four PNGs to [../assets/preview/](../assets/preview): `writeMarks()` draws `icon`, `adaptive-icon`, `splash` and `splash-dark` once for production from mark-o.svg and mark-o-dark.svg and once for the preview from mark-o-preview.svg and mark-o-preview-dark.svg, with the same sizes, ink-radius limits and colour types, and prints each as `preview/<name>.png`. The preview SVGs are `RED_ORANGE` in [../design/jew365-concepts/vector/build.mjs](../design/jew365-concepts/vector/build.mjs): every blue of `BLUE_ORANGE` turned 140 degrees in hue to red with its HSL saturation and lightness kept. Outputs are never edited by hand.
- [icons/export.mjs](icons/export.mjs) writes [../src/components/jewishIcons.generated.ts](../src/components/jewishIcons.generated.ts), the 32 Jewish icons `MitzvahIcon` draws, from the 2026-11-01 icon study (the owner's pick, option ב): `ICONS` of [../design/lab/studies/2026-11-01-icons/icons.mjs](../design/lab/studies/2026-11-01-icons/icons.mjs) for the drawings and the `.tonal` block of [../design/lab/studies/2026-11-01-icons/roles.css](../design/lab/studies/2026-11-01-icons/roles.css) for each colour role's tone (`JEWISH_TONES`: a share of the icon colour and the colour it is mixed with). The `siddur` icon and the three prayers come instead from the round 6 options of [../design/lab/studies/2026-11-01-icons/icons-options.mjs](../design/lab/studies/2026-11-01-icons/icons-options.mjs), the one named by `PICK` (`table`, the owner's pick). Round 7's picks come from [../design/lab/studies/2026-11-01-icons/icons-more.mjs](../design/lab/studies/2026-11-01-icons/icons-more.mjs): `ROUND7` names the option that replaces `shema` (`sunrise`), `brachot` (`window`), `sukkah` (`table`) and `meals` (`plate`), and `TEXT_ICONS` adds ten ids for the siddur tab's texts, from the general group's picks (`lyre`, `eagle`, `suitcase`, `apple`, `storm`, and `mezuzah` and `washingCup`, which reuse the earlier `shema` and `brachot` drawings) and the meals option `perText` (`challah`, the earlier `meals` drawing, `sevenSpecies` and `waterGlass`), and `rings` from round 8's festival options (`OCCASIONS`); it throws on a pick the study does not have. Plain Node: it parses the drawings' small SVG subset (path, rect, circle, ellipse, `<g>`, one linear gradient with its stops; colours that are a role, the gradient or none) into plain data, throws on anything else, and formats the file with Prettier. Run `node scripts/icons/export.mjs` after changing a drawing or a tone; the output is never edited by hand.
- [store/play.mjs](store/play.mjs) is the Google Play command line: plain Node, no dependency, calling the Android Publisher API v3 with a service account (an RS256 JWT exchanged at the key's `token_uri`). It reads the key from `PLAY_SERVICE_ACCOUNT_KEY`, else `~/.store-keys/play-service-account.json`, so no command names the key file. Read commands (`tracks`, `track`, `testers`, `listing`, `details`, `bundles`, `reviews`) open an edit and always delete it. Write commands (`reply`, `upload`, `promote`, `rollout`, `testers-set`) are a dry run by default: the edit is built, validated by Play and deleted; only `--commit` applies it, and `--not-sent-for-review` passes `changesNotSentForReview` when Play asks for it. A dry-run `upload` still sends the AAB to the discarded edit. Output is JSON. The App Store side is the `asc` CLI, set up as [../.claude/skills/store-console/SKILL.md](../.claude/skills/store-console/SKILL.md) describes.
- [store/screenshots.mjs](store/screenshots.mjs) backs `pnpm store:screenshots`, the store screenshots from the web build. Plain Node, no dependency. It runs `expo export -p web` into a temp folder (`--dist <dir>` reuses an export instead), serves a copy from `127.0.0.1` on the first free port of 8091–8099 (never 8081 or 3000), and drives Chrome, else Edge, found like [logo/export.mjs](logo/export.mjs) finds them but Chrome first, headless in a fresh temp profile over the DevTools protocol through Node's built-in `WebSocket`, one browser context per set. Before any app script runs, every page gets the zone `Asia/Jerusalem`, a clock that starts at `NOW` (Wednesday 2026-11-04 15:40, Mincha open) and keeps ticking, light colours, reduced motion, so each entrance animation renders at its end state, and the seed in the MMKV web storage (`localStorage` keys `jew-365\<store name>`, zustand's `{ state, version }`): an onboarded married man in Jerusalem, nusach Sefard, the gold palette, taharah off, notifications on and granted, every id of `DEFAULT_ON_MITZVOT` (read from [../src/stores/useMitzvotStore.ts](../src/stores/useMitzvotStore.ts) as text) on since the first morning of the history, and 30 days of marks up to yesterday: 150 of the 177 that came due (85%), 3 of them late, the Shabbat marks filed through each check-in, Kiddush Levana on its first night, one empty day that leaves a 15-day streak, and Tefillin, the morning Shema and Shacharit done today. The seed's days (`MISSED`, `LATE`, `KIDDUSH_LEVANA`) and the report's week are dates tied to `NOW`, so moving `NOW` moves them too; the script refuses a seed day outside the 30 days before it. The web notification shim reports permission `unknown` whatever the browser allows, so the copy it serves has the bundle's one `setNotificationPermission('unknown')` rewritten to `'granted'`, as on a phone that allowed notifications, and it fails when it finds no such call or more than one. It captures `SCREENS` (home, the siddur tab, the Mincha reader opened on Ashrei through its `section` param, history, Settings, Rabbi Shimon bar Yochai's page, the report of the week ending 2026-10-31) in four sets, `appstore-he` and `appstore-en` at 402x874 and device scale 3 (1206x2622), and `play-he` and `play-en` at 400x800 and device scale 2.7 (1080x2160, within Play's 2:1 limit; at 360x640 home's day arc crowded its time card), and writes each as an opaque RGB PNG (colour type 2) to `<out>/<set>/<n>-<screen>.png` (`--out`, default `~/Downloads/jew365-store-screenshots`; `--sets` and `--screens` narrow a run). Each capture waits for the fonts and two seconds of unchanged page text, and the run fails on a redirect away from the route, a visible `undefined`, `null`, `NaN` or `Invalid Date`, a raw i18n key, the error boundary or an unmatched route, or an uncaught exception. On home it then scrolls the zmanim chip row so the next zman's chip is centred, as a phone shows it: React Native Web's horizontal `scrollTo` does nothing in a right-to-left row, so in Hebrew the row would stay at dawn. The mitzvah screen is left out, because the web build draws its switches broken.

## Local Contracts

- Scripts must be plain Node and cross-platform. A shell-specific script silently breaks every non-Windows contributor and CI runner; that is why `pnpm web` no longer shells out to PowerShell.
- Scripts must be non-interactive: they run from `pnpm` scripts and in CI, where nothing can answer a prompt.
- The notification config plugin must stay aligned with scheduler constants in [../src/services/AGENTS.md](../src/services/AGENTS.md), especially `MARK_DONE`.
- Generated native folders are not owned here; the plugin source is the durable artifact.
- Set a test zone through the `env` of a spawned Jest process. Assigning `process.env.TZ` inside Jest does nothing, because `setupFiles` get a copy of `process.env`, so the clock never moves. A `TZ=` prefix in Git Bash is dropped for native programs as well; PowerShell `$env:TZ` and cmd `set TZ` do work.

## Work Guidance

- Prefer narrow script changes over adding new tools.
- For config plugin changes, reason through both manifest mutations and generated Kotlin output.

## Verification

- Run `pnpm web` or `node scripts/free-port.js <port>` after changing [free-port.js](free-port.js).
- Run `pnpm test:tz` after changing date or timezone handling.
- After changing [test-timezones.js](test-timezones.js) or [jest-timezone-setup.js](jest-timezone-setup.js), check that the guard still fails a run whose zone did not apply, e.g. `JEST_TZ=Pacific/Kiritimati npx jest src/theme` from Git Bash.
- Run `pnpm test -- scripts/__tests__/publishUpdate.test.js` after changing [publish-update.js](publish-update.js). For the inlining, `npx expo export --platform android --no-bytecode --clear` with `EXPO_PUBLIC_UPDATE_NUMBER` set must compile `appVersionLabel()` to that number, and to `0` without it.
- Run `pnpm guide:build`, then `pnpm test -- src/data/__tests__/guide.test.ts scripts/__tests__/publishUpdate.test.js`, after changing [guide/build.js](guide/build.js) or [publish-update.js](publish-update.js).
- Run `pnpm doctor` after changing Expo config plugin behavior.
- After changing [logo/export.mjs](logo/export.mjs), run `pnpm logo:build` (it prints each PNG's size, colour type and ink radius), look at the PNGs, then `pnpm test -- scripts/__tests__/logoAssets.test.js scripts/__tests__/appConfig.test.js src/components/__tests__/AppLogo.render.test.tsx`, and check that `git status --short assets src/components docs` shows no production file changed. For a change to the splash, icon or notification wiring, `npx expo prebuild --platform android --clean --no-install` and read `res/values/styles.xml`, the `splashscreen_logo` drawables, `mipmap-anydpi-v26/ic_launcher.xml` (it must hold a `<monochrome>` layer), `values/colors.xml` and `values-night/colors.xml`; delete `android/` afterwards.
- After changing [withAndroidBackupRules.js](withAndroidBackupRules.js), run `pnpm test -- scripts/__tests__/androidBackupRules.test.js`, then `npx expo prebuild --platform android --no-install` and read `android/app/src/main/res/xml/` and the `<application>` attributes of the generated manifest; delete `android/` afterwards. On a device or emulator, `adb shell bmgr enable true` and `adb shell bmgr transport com.android.localtransport/.LocalTransport`, then, with the app opened once and backgrounded (a force-stopped app answers "Backup is not allowed"), `adb shell bmgr backupnow com.jew365.app`, `adb shell pm clear com.jew365.app` and `adb shell bmgr restore 1 com.jew365.app` (the token from `bmgr list sets`) exercise a real backup and restore; as root, `tar -tvf /data/data/com.android.localtransport/files/1/_full/com.jew365.app` lists exactly what was backed up. Verified on 2026-10-14 (API 37), under the app's previous package: the archive held the three `BACKED_UP` files and nothing else, and the restored install opened on home with its settings and streak.
- After changing [withAndroidLegacyHebrewLocale.js](withAndroidLegacyHebrewLocale.js) or a Hebrew file under [../locales/](../locales), run `pnpm test -- scripts/__tests__/androidLegacyHebrewLocale.test.js`, then `npx expo prebuild --platform android --no-install --clean`, with and without `APP_VARIANT=preview`, and read `app_name` in `res/values-b+he` and `res/values-b+iw` (they must match); delete `android/` afterwards. On a built APK, `aapt dump badging` must print `application-label-iw` in Hebrew. Verified on 2026-10-25 by prebuild for both variants.
- After changing [store/play.mjs](store/play.mjs), run every command against a local mock of the API (a throwaway RSA key in a fake service-account file whose `token_uri` and `PLAY_API_ROOT` point at the mock), check each request path and body, then run the read commands against Play itself. Never run a write command with `--commit` as a check. Verified on 2026-10-26 against a mock (all 15 cases, including the dry runs and the argument errors) and against Play with the real service account (`tracks`, `testers alpha`, `bundles`, `details`, `listing iw-IL`, `reviews`).
- After changing [store/screenshots.mjs](store/screenshots.mjs), run `pnpm lint`, then `pnpm store:screenshots --out <a temp folder>` and open every PNG: the day arc and the open Mincha on home, the reader on Mincha's Ashrei, the next zman's chip centred in both languages, a 15-day streak in history, Settings under its search, the tzaddik's page and the report of 25–31.10, in both languages and both sizes, with no banner, spinner, error, onboarding screen or wrong direction. Verified on 2026-11-01 in Chrome: all 28 images, the Play sets at 1080x2160.
- Run `pnpm check:dox` after changing [check-dox.js](check-dox.js) itself, and confirm it still fails on a deliberately broken link before trusting a pass.
- Use a dev client or native build to verify Android notification-action behavior.
